# Inspecto Frontend

Фронтенд на React 18, TypeScript и Vite с синей темой и демонстрационным сценарием подготовки чек-листа ТО. Авторизация и подключение к API на первом этапе отсутствуют; приложение открывается сразу.

## Запуск

Нужен Node.js 22.14+ и npm.

```sh
npm ci
npm run dev
```

Адрес: http://localhost:3000 (если порт занят, Vite выберет следующий).

```sh
npm run build
npm run lint
npm test
npm run preview
```

## Структура

- `src/pages` — страницы; главная со сценарием подготовки чек-листа и страница 404.
- `src/navigation` — маршруты, новые страницы подключаются внутри MainLayout.
- `src/shared` — общие компоненты и базовый лэйаут.
- `src/styles` — стили, типографика, цветовые переменные.
- `src/assets` — локальные шрифты и SVG.

Из ps-frontend перенесены Button, Card, TextInput, TextArea, Checkbox, Toggle, Tag, TagWithCloseIcon, Skeleton, ThreeDotsLoader, LiveClock, стили и шрифты. MainLayout адаптирован: шапка Inspecto, сворачиваемая навигация и область страницы. Сохранены размеры и оформление исходного проекта; основная палитра изменена на синюю. Сервисы авторизации, роли, API, WebSocket и Sentry не подключены.

Импорты через `@/` ведут в `src/`. SVG-компоненты импортируются с `?react`. Стили компонентов — CSS Modules. Файл package-lock.json хранится в Git.

Для production-размещения отдавайте `dist/`, направляя неизвестные пути на `index.html` (SPA fallback).

## Сценарий чек-листа

1. Выберите Excel (.xlsx/.xls, один файл до 20 МБ) или откройте пример.
2. Проверьте адреса и количество зон в таблице; можно добавлять и удалять дома.
3. Подтвердите качество данных. Изменение любой ячейки сбрасывает подтверждение.
4. Сформируйте чек-лист, отредактируйте работы, зоны, периодичность и примечания.
5. Сохраните результат на устройстве или скачайте Excel без предварительного сохранения. Экспорт включает все строки независимо от поиска, фильтра и страницы.

Пустые адреса, дубликаты, отрицательное/дробное количество зон и пустые работы блокируют переход или экспорт. Для демоверсии действует предел 500 зон, по 100 каждого типа на дом. При возврате к шахматке чек-лист пересоздаётся после предупреждения.

### Ограничения деморежима

API и реальные шаблоны не предоставлены. Содержимое выбранного Excel **не читается и не отправляется**: адаптер возвращает три демонстрационных дома. Названия зон, состав работ и периодичность условные и не являются действующим регламентом ТО. В экспортируемом файле есть соответствующая пометка.

Текущая рабочая сессия автоматически восстанавливается из localStorage (`inspecto:workspace:v1`). Кнопка «Сохранить» дополнительно сохраняет последний подтверждённый снимок (`inspecto:last-saved-checklist`). Серверного сохранения, синхронизации и истории документов пока нет. При очистке данных браузера локальная сессия теряется.

### Подключение API

- `src/features/checklist/types.ts` — модели и контракт `ChecklistService`.
- `services/mockService.ts` — асинхронный адаптер загрузки → получения черновика → подтверждения → получения чек-листа → сохранения.
- `components/UploadPanel`, `DraftEditor`, `ChecklistEditor` — независимые экраны сценария.
- `ChecklistFlow.tsx` — переходы, состояния загрузки/ошибки, повтор действий и подтверждение сброса.
- `services/exportChecklist.ts` — клиентский экспорт XLSX; ExcelJS подгружается только при скачивании.

При появлении API замените адаптер реализацией `ChecklistService`, согласуйте модели домов/зон и шаблон ТО, добавьте ожидание фоновых задач по контракту бэка. Текущие методы с job ID — внутренний интерфейс клиента, а не согласованный серверный API.

`npm test` проверяет валидацию, генерацию по исправленным данным, восстановление сессии и содержимое Excel после повторного чтения.
