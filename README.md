# Inspecto Frontend

Фронтенд на React 18, TypeScript и Vite с синей темой и демонстрационным сценарием подготовки чек-листа ТО. Авторизация и подключение к API на первом этапе отсутствуют; приложение открывается сразу.

## Запуск

Нужен Node.js 22.14+ и npm.

```sh
npm ci
npm run dev
```

Адрес: http://localhost:3000 (если порт занят, Vite выберет следующий).

```sh
npm run build
npm run lint
npm test
npm run preview
```

## Структура

- `src/pages` — страницы; главная со сценарием подготовки чек-листа и страница 404.
- `src/navigation` — маршруты, новые страницы подключаются внутри MainLayout.
- `src/shared` — общие компоненты и базовый лэйаут.
- `src/styles` — стили, типографика, цветовые переменные.
- `src/assets` — локальные шрифты и SVG.

Из ps-frontend перенесены Button, Card, TextInput, TextArea, Checkbox, Toggle, Tag, TagWithCloseIcon, Skeleton, ThreeDotsLoader, LiveClock, стили и шрифты. MainLayout адаптирован: шапка Inspecto, сворачиваемая навигация и область страницы. Сохранены размеры и оформление исходного проекта; основная палитра изменена на синюю. Сервисы авторизации, роли, API, WebSocket и Sentry не подключены.

Импорты через `@/` ведут в `src/`. SVG-компоненты импортируются с `?react`. Стили компонентов — CSS Modules. Файл package-lock.json хранится в Git.

Для production-размещения отдавайте `dist/`, направляя неизвестные пути на `index.html` (SPA fallback).

## Сценарий чек-листа

1. Выберите Excel (.xlsx/.xls, один файл до 20 МБ) или откройте пример.
2. Проверьте адреса и количество зон в таблице; можно добавлять и удалять дома.
3. Подтвердите качество данных. Изменение любой ячейки сбрасывает подтверждение.
4. Сформируйте чек-лист, отредактируйте работы, зоны, периодичность и примечания.
5. Сохраните результат на устройстве или скачайте Excel без предварительного сохранения. Экспорт включает все строки независимо от поиска, фильтра и страницы.

Пустые адреса, дубликаты, отрицательное/дробное количество зон и пустые работы блокируют переход или экспорт. Для демоверсии действует предел 500 зон, по 100 каждого типа на дом. При возврате к шахматке чек-лист пересоздаётся после предупреждения.

### Обработка сантехники

Загруженная XLSX-шахматка читается локально (формат предоставленного файла Крауля: дома в первой строке, помещения и системы в первом столбце). XLS для шахматки не поддерживается. «Открыть пример» сохраняет прежний демонстрационный сценарий.

Пул из 78 работ извлечён из предоставленного файла `Шаблоны_Прототипы_ЧЛ_Сантехника_и_Периодичность.xls` и хранится в `data/plumbing.json`. Источник каждой работы — лист и строка. ТО1.1 — 8 раз в месяц, ТО1 — 1 раз в месяц, ТО2 — 1 раз в три месяца. ТО3 и годовые листы исключены. Проценты прочитаны с учётом формата исходной ячейки.

Незональные работы повторяются по количеству помещений. Зональные — по количеству зон соответствующей системы, без умножения суммарного количества зон на число помещений. Если количество помещения отсутствует, формирование блокируется до уточнения. Ноль означает отсутствие помещения. Ноль исключает работу. Привязка каждой зоны к ИТП/насосной задаётся в черновике; устаревшие назначения блокируют формирование и выгрузку. Текстовые пояснения сохраняются для проверки. Сезонные месяцы сохраняются в примечаниях, календарная фильтрация не применяется.

Экспорт включает дом, работу, экземпляр помещения/зону, помещение, систему, узел, погрешность, фотоотчёт и атрибуты (Да/Нет), периодичность и источник. Поля доступны для правки. Backend не подключён; сохранение выполняется в localStorage.

### Подключение API

- `src/features/checklist/types.ts` — модели и контракт `ChecklistService`.
- `services/mockService.ts` — асинхронный адаптер загрузки → получения черновика → подтверждения → получения чек-листа → сохранения.
- `components/UploadPanel`, `DraftEditor`, `ChecklistEditor` — независимые экраны сценария.
- `ChecklistFlow.tsx` — переходы, состояния загрузки/ошибки, повтор действий и подтверждение сброса.
- `services/exportChecklist.ts` — клиентский экспорт XLSX; ExcelJS подгружается только при скачивании.

При появлении API замените адаптер реализацией `ChecklistService`, согласуйте модели домов/зон и шаблон ТО, добавьте ожидание фоновых задач по контракту бэка. Текущие методы с job ID — внутренний интерфейс клиента, а не согласованный серверный API.

`npm test` проверяет валидацию, генерацию по исправленным данным, восстановление сессии и содержимое Excel после повторного чтения.

## Проверка, предпросмотр и история

- «Редактор»: количества, привязки зон и работы. «Отменить изменение» / «Повторить» — до 20 последних изменений текущей сессии, включая удаление работ. После перезагрузки стек отмены очищается.
- «Проверка»: ошибки блокируют формирование/экспорт; возможные дубли и неиспользуемые привязки — предупреждения. Нажатие открывает соответствующий дом или работу. Переход к исправлению шахматки из готового чек-листа сначала сохраняет версию и требует пересоздать чек-лист.
- «Предпросмотр Excel»: те же строки и колонки, что в экспортируемом XLSX, без фильтров редактора; постраничный просмотр и причины исключения пунктов (нулевые количества, удаление пользователем). Годовые/полугодовые работы исключены целиком, сезонные ограничения остаются примечаниями.
- «История»: полные независимые снимки шахматки, назначений и чек-листа в IndexedDB (`inspecto-documents`). Сохранение вручную, перед формированием/выгрузкой/сбросом, а также перед восстановлением другой версии. Восстановление не удаляет текущую работу: она архивируется первой. Ошибка записи отменяет замену данных и показывается пользователю.

История локальна для браузера и адреса приложения, не синхронизируется с сервером. Очистка данных сайта удалит её. Рабочая сессия по-прежнему восстанавливается из localStorage.
